# 设计变更记录

本文只记录会影响当前设计判断的变化。每条记录必须引用 `.memory/design.md` 中存在的锚点，并说明当前系统现在应当如何成立。

## 2026-09-02 - 统一执行状态语义和曲线生命周期

锚点：[执行-状态机]，[执行-展开与ETA]，[接口-前端契约]，[接口-事件契约]，[前端-派生与展示规则]

原因：执行 phase 同时存在于后端引擎、公共快照、前端 store 和组件布尔变量中，终态又被引擎立即改回空闲，导致状态含义可能矛盾；EIS 与 IVT 曲线因此具有不同的完成后生命周期，节点增量事件也缺少执行身份，刷新后无法完整恢复循环状态。

变更：共享契约统一七个执行 phase；两端使用按 `is`、`can`、`keeps`、`view` 等自然语言能力编组的状态表；后端终态保留到显式重置，新执行在重置前拒绝创建；快照增加循环进度和节点结果，节点计时增加迭代路径；节点与循环事件携带 execution id，前端 store 按执行、节点和进度分组并从完整快照水合。

设计影响：业务 phase 只有一个后端事实源，命令 pending 与业务状态分离；每个执行和节点的数据彼此隔离，所有测量曲线在完成、失败或取消后统一保留，在重置时统一清空；未来增加暂停类状态时只需扩展共享 phase 和两端状态能力表。

验证：运行共享契约生成、共享类型构建、前端 TypeScript/生产构建、Python compileall、状态表导入断言、版本一致性和 `git diff --check` 的基础烟囱检查。

## 2026-09-02 - 修正循环进度重复加一

## 2026-09-02 - 分离测量图表自动跟随与用户选择

锚点：[前端-派生与展示规则]

原因：测量图表的自动聚焦 effect 在用户切换图表类型后立即重新执行，并且只依赖快照保留的 `currentStep` 而不判断执行是否 active，导致运行中和终态都可能把视图抢回当前或最后节点；复用同一图表实例还可能保留上一节点的 series。

变更：面板首次打开时仅跟随 active 执行中的测量节点，用户手动选择类型、节点或批量范围后，本次打开期间不再自动覆盖选择；图表组件按 execution id 和节点 id 重建，切换时从各自的 execution/node/iteration 缓存恢复或显示空图。

设计影响：执行快照决定默认聚焦，但不再代替用户当前的查看选择；IVT 与 EIS 的展示实例具有一致的执行和节点边界。

验证：`pnpm version:check`、`pnpm --filter @zahnerflow/types build`、`pnpm --filter zahnerflow-flowgram build`、测量图表组件定向 ESLint 与 `git diff --check` 通过；当前仓库未包含 Vitest 测试文件，前端测试入口因无用例可运行而退出。

## 2026-07-10 - 修正 EIS 扫描控制参数映射

锚点：[设备-驱动调用]

原因：前端已经保存 `eisScanDirection` 与 `eisScanStrategy`，但 Zahner 真机逻辑读取的是 `eis_scan_direction` 与 `eis_scan_strategy`。归一化遗漏这两个字段时，真机会回退到 `START_TO_MIN` 和 `SINGLE_SINE`，覆盖用户在界面的选择。

设计影响：测量配置在进入真机或模拟器前必须完整归一化；EIS 扫描方向、起始频率和频率边界是一组不可拆分的参数，显示、ETA 和设备执行应以同一份归一化参数为基础。

验证：核对 Zahner 官方 `thales_remote` 库对 `START_TO_MAX` 与 `START_TO_MIN` 的定义；运行 EIS 参数归一化测试和后端测试。

设计影响：EIS 产品方向与 Thales 第一段方向必须在真机边界显式转换，禁止把产品方向枚举直接透传给设备。
