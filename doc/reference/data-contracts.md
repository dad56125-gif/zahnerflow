## 命名与单位

数据库物理列、Python 局部变量使用 `snake_case`；业务 JSON 和 TypeScript 使用 `camelCase`。必要的边界转换只做一次，不能同时在响应中复制两份字段，再让每个消费方反复猜测。

| 含义 | 数据库存储 | 业务输出 | 说明 |
| --- | --- | --- | --- |
| 执行 ID | `executions.id`、外键 `execution_id` | `executionId` | 报告、运行状态、命令均引用真实执行 ID |
| 工作流 ID | `workflow_id` | `workflowId` | 定义身份与某次执行身份分开 |
| 原节点位置 | `original_index` | `originalIndex` | 0 起始，不等同于展开位置 |
| 展开位置 | `unrolled_index` | `unrolledIndex` | 0 起始，展示序号可加 1，筛选不得改写身份 |
| 步骤耗时 | `actual_seconds` | `actualSeconds` | 秒；缺失保留空值，不能当作实测 0 秒 |
| 执行耗时 | `executions.duration` | 报告 `durationMs` | 毫秒；保留现有物理列以避免无意义数据搬迁 |
| 执行起止 | `start_time`、`end_time` | 报告 `startedAt`、`endedAt` | 实时执行快照保留其既有 `startTime`、`endTime` 契约，禁止在同一载荷复制别名 |
| 操作者 | 每次执行的 `workflow_snapshot.ownerName` | `ownerName` | 同一工作流可由不同操作者执行，不得继承定义创建者 |
| 用户档案 | `users.id`、`username`、`created_at` | `id`、`user`、`createdAt` | 仅档案出口做 username → user 映射，前端不生成业务身份 |
| 数据点数量 | 新结果 JSON 的 `dataPoints` | `dataPoints` | 0 是有效值；旧 `data_points` 等只在历史读边界归一化 |

`/health` 是运维响应，保留现有下划线字段，并新增 `schema_version` 用于报告应用迁移版本。设备协议寄存器、物理量与驱动参数各有实际含义，不能仅因名字相似就合并；协议别名由对应设备适配边界处理。

工作流环境来源是测量前读取的实际状态，由 `runtime/filename_environment.py` 选择环境标签，再交给既有 `build_filename`；整数标签不回写设备状态或原始测量数据。温度工步上下文只属于本次执行的 `ExecutionControl`。具体规则及验证见下文；直接测量的保存路径与格式化逻辑未修改。

### 命名方案与工况示例（已实施，隔离验证通过）

以下四项为已实施的工作流文件名环境字段判定与取整规则，不下发校准、清零或任何设备命令，也不把容差称为厂家精度。

- A 温区：温度以本次有效温度工步目标 T 为中心，沿用已有 `tolerance` 判定，`T±tolerance` 含边界。没有有效温区但读数有效时按实测整数标注，不借用旧任务目标。

- D 取整与比较：分支和阈值比较都使用未经命名取整的有效原始读数；只有最终命名时才取 1 ℃、1 sccm 整数。绝对值四舍五入后恢复符号，半单位进位，零不带负号，不更改原数据精度。读数失败、离线或 NaN 仍省略对应字段；气体名称排序和秒级时间不变。

### 核查结论更正与验证边界

- 上轮固定时钟下的直接函数调用只能证明人为构造同名时的保存行为，不能证明正常串行实验会在同秒产生重名；撤回将其列为当前实际问题的判断，不增加防重名机制。
- 同名气体的多通道假设不符合用户当前样品场景，不作为本次问题或修改范围。
- 高级节点的同一父节点可能分散到多个时间目录；旧行为下已对同一配置分别固定两个子步骤开始时间，确认输出目录不同。文件和高级目录的本地时间 / UTC 混用已在固定 UTC+8 时钟下复现。四种高级节点单文件写入改为按父执行一次打开一个文件后，不再按子步骤重算路径；该条只保留旧行为证据。
- 当前 `NodeConfiguration.ts` 的节点参数没有自定义文件名入口。已按用户要求删除 `outputFileName → filename`、`filename=measurement` 缺省与属性名称标签，重新生成共享别名表。源码及生成类型无该别名残留；参数归一化与自动命名冒烟检查、共享类型及前端生产构建通过。真实文件名局部变量和测量结果中的 filename 仍表示自动生成的文件名。应用版本 `2.12.7 → 2.12.7`，仅清理未接入代码，不升级。
- 数值取整损失文件名精度，不同参数可得到相同标签；例如 `1.0004 V` 和 `1.00049 V` 均为 `1000mV`。原始测量参数不因命名取整而变化。
- 恒流 EIS 的命名分支只读 `eis_current`，驱动另读 `enable_dc_bias`；人为传入 false 才能进入两者不一致的分支。当前恒流 EIS 界面没有该开关，归一化默认 true，正常界面路径按所设电流命名和执行。撤回将异常参数分支直接列为当前界面故障的判断，不修改 EIS 行为。

既有验证仅覆盖隔离函数、模拟器和执行器，不证明现场发生重名、重复气体通道或恒流偏置开关误操作。四种高级节点单文件保存已通过隔离单元与普通回归（时间列、有限值拒绝、常量内存、单句柄逐点 `flush()`、收尾 `fsync`/`close` 错误保留、写入失败叠加设备关闭失败均按失败上报），并完成正常集成 75 项、故障注入与工步间确定性停止 49 项、报告读取 15 项及报告/取消 focused 40 项；均为隔离、模拟器与假设备验证，未连接真机。

### 高级节点单文件保存（已实施）

范围更正（2026-10-15）：本方案只作用于四种高级节点 `galvanostatic_step_ramp`、`potentiostatic_step_ramp`、`galvanostatic_switching`、`potentiostatic_switching`。一次实验指一个高级节点的一次执行，包含该次执行展开出的全部子工步；它不是整个工作流一个 CSV，也不改变普通 OCP、CA/CP、LSV、EIS 的文件与仪器行为。此处不再保留“全工作流统一 CSV”的说法。

已实施：四种高级节点在该次父执行开始时创建并打开一个 CSV 并写一次表头，每条有效原始测量数据立即追加一行并 `flush()`，不反复打开、不读回或重写已有数据；该次执行的全部子工步沿用同一个句柄。正常结束、用户停止、采样异常或写入异常时统一 `flush()`、`os.fsync()`、关闭。写入、flush、fsync 或关闭错误向上传播为执行失败并安全关闭设备，不打印日志后继续，也不误报保存成功；用户取消不掩盖写入或收尾错误。写入层不新增写入线程、消息队列、批量缓存、定时刷盘或自动拆分。保存端使用常量内存：只保留计数、总和与极值，不为保存累积全部历史行；累计 `Time (s)` 取父执行开始的单调时钟，工步统计只针对当前工步实测电流；计数与在线统计在 `writerow` 成功后、`flush()` 之前更新，`dataPoints` 语义为已完成追加的行数，因此一次 `flush()` 失败而收尾 `flush()` 成功时 CSV 行数与归档点数仍一致，异常时不宣称持久化成功。实时绘图回调、每工步统计和报告保留。单文件身份由既有命名生成器 `logic._prepare_output_path` 得到基础名后拼接本次执行 `execution_id` 与首个展开工步身份，排他创建，绝不覆盖已有实验；`build_filename` 不新增身份分支。运行时已接入：真实 Planner、Engine 与模拟器端到端验证通过；报告按 `Step` 恢复各工步曲线并通过读取测试；未连接真机。

边界澄清（2026-10-15）：这里的常量内存只指保存端与在线统计；报告仍按既有契约生成曲线 `points` 数组，其内存随需要展示的点数增长，不把整个实验或整份报告描述为恒定内存。新 CSV 的流式读取只去掉额外的整表 `rows` 副本，不改变前端实时绘图缓存和报告曲线需求。

表头按父节点类型固定为以下列序列，不含隐藏列：

| 列序 | 恒流阶梯 | 恒压阶梯 | 恒流切换 | 恒压切换 |
| --- | --- | --- | --- | --- |
| 1 | `Time (s)` | `Time (s)` | `Time (s)` | `Time (s)` |
| 2 | `Step time (s)` | `Step time (s)` | `Step time (s)` | `Step time (s)` |
| 3 | `Step` | `Step` | `Step` | `Step` |
| 4 | `Set current (A)` | `Set potential (V)` | `Cycle` | `Cycle` |
| 5 | `Potential (V)` | `Potential (V)` | `Phase` | `Phase` |
| 6 | `Current (A)` | `Current (A)` | `Set current (A)` | `Set potential (V)` |
| 7 | 无此列 | 无此列 | `Potential (V)` | `Potential (V)` |
| 8 | 无此列 | 无此列 | `Current (A)` | `Current (A)` |

`Time` 为该高级测试累计时间，不随步骤重置；`Step time` 为当前步骤内时间。`Step`、`Cycle` 从 1 开始，切换 `Phase` 使用 1/2。设定值取当前工步实际下发值，A/V/s 使用原始精度，不加入功率、面积归一化或其他派生列。同一次执行内子工步沿用同一个单文件，因此不再按子步骤新建文件或新建目录；父高级节点在循环内多次执行时每次执行各自一个文件，不串到上一次。从中间工步启动（`startFromUnrolledIndex`）时 `Step` 保留真实编号，文件在第一次执行的工步打开。

报告读取（`report_measurements.py`）按每个子步骤的本地 `Step time (s)` 与 `Step` 列过滤，只取该工步的行，不再把整个父节点数据算成同一曲线；新高级 CSV 改为单次流式读取并按 `Step` 分派，不保留整表 `rows` 列表，只保留报告契约需要的曲线 `points` 数组。普通旧 CSV 的 32 MiB 上限与整表读取行为保持不变。高级路径统计已在写入层实现：由 sink 在采集时累计当前工步实测电流，`real_device.measure` 与 `simulator_device.measure` 对高级文件不再整表调用 `_calculate_stats`，不再每子步骤重读累计 CSV。运行时接线与报告读取已由对应模块接入：引擎收尾只调用通用资源 `close`，同一次父执行的 sink 在子工步间复用，失败或取消步骤保留相应终态及已落盘部分结果，并保留 `csvPath` 与本工步已保存点数。报告读取 15 项（含总文件 >32 MiB 但单工步仍可报告）与报告/取消 focused 40 项通过；报告仍按既有契约生成曲线 `points` 数组，其内存随需要展示的点数增长。

### 历史候选方案（已由上述实施要求替代，不描述当前行为）

以下内容保留为历史讨论，只说明当时评估过的候选做法，不代表当前实现。已被替代的候选包括：每行 `flush()` 后立即 `os.fsync()`；按固定短时间窗口 fsync、步骤结束或退出再同步；只在文件层设固定上限、不限制保存端内存；先累计当前子步骤全部记录再覆盖写 CSV。当前实现取“每点 `flush()`、收尾一次 `fsync()`”的最小资源方案，不逐点 `os.fsync()`，不做定时刷盘。

先前候选的完整评价文字、逐点同步开销表与待审阅边界不再作为当前设计承诺，只保留结论：忽略了一次性表头后，逐行追加不必保留全部测量记录；整个应用内存并非全局有上限。`useMeasurementStream.ts` 的实时绘图缓存本次不改造，不加上限、不抽稀。普通旧 CSV 仍保留 `32 * 1024 * 1024` 字节整表读取上限与既有错误提示；新高级单文件不能沿用该整表限制，合并后总文件超过 32 MiB 而单个子工步很小时，原有“每工步可报告”的能力必须保持，因此改为单次流式读取并按 `Step` 分派，不物化整表 `rows`。该“总文件超过 32 MiB、单工步仍可报告”的场景列入本次验收。

## 历史数据库升级

未版本化数据库（`user_version=0`）在一个事务中创建缺失表、补齐允许为空或有默认值的列，再创建索引，最后写入迁移版本 1。已有字段、业务记录、测量文件路径保持不变；必填列或主键异常会报错并回滚，未来版本拒绝降级打开。

后续结构变更必须增加迁移阶段与数据保留验证。不得把更新应用版本作为迁移，也不能修改已经执行过的迁移行为来偷偷改变旧库。

报告结果别名集中在 `report_service.normalize_stored_result`。这是读取已存在实验数据的明确边界，不是提供第二套公开协议。前端不再接受旧报告字段；外部消费者需根据 API 4.1.0 和报告 3.0 更新。历史工作流节点参数与设备协议仍有各自的兼容读取，不能把报告规范化理解为所有设备参数都已强类型化。

产物来源与文件展示分开：后端补齐时按执行、节点、路径避免重复补入，并保留各节点的来源关联；前端展示按物理路径去重。同一个目录被多个步骤引用，不代表多份物理文件。
