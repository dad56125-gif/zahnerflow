# ZahnerFlow 整体优化交付报告

完成日期：2026-09-08。版本：**1.0.11 → 2.2.1**。所有改动在 `codex/project-optimization-20260908` 分支完成，开始前已固定基线标签 `baseline/optimization-20260908-v1.0.11`，指向 `cbd8f58`。

## 项目定位与最终方向

ZahnerFlow 继续面向本地实验工作站：用节点组织电化学测量、温度、流量和循环，由一个 Python 进程执行并保存结果。React/Electron 是操作与观察界面，CLI/Agent 是另一种指令入口；它们共用 AppRuntime、SQLite 和设备连接。

视觉沿用当前主界面的暗色玻璃面板、蓝色主操作、统一图标和语义状态色，已固定为 [设计规范](design-system.md)。代码保持 TypeScript 组件/钩子/状态选择器与 Python 运行时/规划/驱动的分工。此次重点是减少重复事实与隐式桥接，不引入新服务或额外设备端口。

适用范围仍是本地单操作者、一次一条活跃实验；用户档案区分设置和记录，不提供多租户鉴权。CLI 的新增不会改变这一边界。原始全局评估保留在 [优化前报告](project-assessment-2026-09-07.md)。

## 验收边界与后续维护

- 真机 Thales/Zahner、炉温控制器和 MFC 的长时间实验尚未进行。本次模拟输出不能作为仪器测量或科学有效性证据；模拟 ISM 是占位文件。
- 已构建并运行 Windows 后端及编译桌面壳；没有重新生成/安装最终 Electron 安装器，也没有验收 macOS、代码签名或所有最低依赖版本组合。PyInstaller 有第三方可选隐藏导入警告，实际使用的模拟与地图路径通过，不能据此推断所有第三方路径都已覆盖。
- PDF 检查确认导出调用结束与模块无错误，不包含导出文件逐页排版验收；原有截图式 PDF 仍是截图式，不是可编辑矢量科学报告。
- 核心设计规范已固定，仍允许图表、硬件物理量和装饰渐变具有业务专色；没有把全仓库所有颜色字面量机械替换。新 UI 必须遵守同一规范。
- 数据库 DDL 和报告命名已集中；具体科学节点 `config` 仍是通用对象，历史工作流与设备适配仍有必要别名。完整参数 Schema 可按设备逐步补齐，不应把当前能力发现宣称为完整科学参数验证。
- 设置和实验记录窗口仍较大，但裁剪、预览、状态、请求边界已拆开。后续新增需求应继续沿这些职责扩展，避免为了减少单文件行数而新增状态桥接。

下一次修改先读 `.memory/design.md` 与对应规范；前后端契约先改共享模型，持久化变化增加迁移，样式遵循固定令牌。上述未覆盖范围是后续验收边界，不影响已完成优化的回溯与审阅。
