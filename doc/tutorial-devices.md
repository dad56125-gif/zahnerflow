# 实验信息与设备控制教程

状态：2.5.0 独立教学分支。归属：教学功能维护者。复核日期：2026-09-20。

## 准备实验信息

11 步演示：未填写信息时点击运行 → 查看缺少用户、项目、样品的提示 → 选择用户 → 再次运行仍提示项目与样品缺失 → 打开用户配置 → 填写路径、项目、样品 → 返回并运行隔离 OCP 样例。

工作站与单个 OCP 节点属于课程前置状态。本课不操作工作站选择器。基础路径用于说明保存位置，后端 `MISSING_RUN_METADATA` 必填项是用户、项目名称、样品名称，不能把基础路径误称为该错误的必填项。

当前 Toolbar 在警告显示期间拦截再次点击，教程展示按钮暂不可用和流程保持未启动，补齐信息后再开始，不修改真实启动策略。错误内容采自 `routers/executions.py` 的实际 409 响应，由原有 `useWorkflowExecution` 和 Toolbar 展示。

## 连接与控制管式炉

15 步：打开设备窗口 → 刷新端口 → 选择列表与端口 → 连接 → 辨认 PV/SV/MV → 程序段页 → 读取程序 → 返回监控 → 运行 → 保温 → 继续 → 停止 → 断开 → 关闭窗口。

使用原有 `DeviceConnectionPanel`、`ProgramEditor`、`StatusPanel`。回放模拟器的默认室温程序，演示控制和状态变化；不声称默认程序是 SOP 升温方案。真实实验必须核对炉内程序，停止后仍需观察 PV，断开通信不代替停止程序。

## 连接与控制流量计

13 步：打开窗口 → 刷新端口 → 选择列表与端口 → 连接并自动扫描 → 核对地址、气体、量程 → 输入 50 sccm → 设置 → 观察实际与设定 → 输入 0 → 下发归零 → 断开 → 关闭窗口。

使用原有 `MFCModal`、`MFCDeviceCard`。连接操作由真实 hook 发起 32–80 逐地址扫描。32 号教学通道为 N₂，量程 200 sccm，50 sccm 仅为控件演示值，不替代 SOP 配气参数。归零使通道回到空闲分区；断开通信不等于归零命令。

## 数据与隔离

- `deviceLessons.ts` 定义操作步骤与 DOM 验收；`tutorialDeviceScenario.json` 是生产教学资源，采自本项目 Python 正常模拟器及实际 FastAPI 路由，包含命令返回、状态快照、逐地址扫描快照和信息缺失错误。
- 采集使用独立临时 SQLite 数据目录及进程内 ASGI 请求，连接只使用 `COM_SIMULATOR`，未启动另一台前端或调用服务中的真实设备。采集脚本及证据位于忽略目录 `.codex-run/tutorial/`。
- 教学仍使用原 App、业务组件、runtimeClient 与设备状态事件。教学设备写命令只匹配已采集动作，未知命令报错；只有预览和 ETA 可请求实际后端。
- 管式炉与流量计 hook 在会话开始时保存状态及版本计数，创建教学状态；会话退出等待请求完成，恢复原状态、历史、日志与版本，随后处理缓存的真实事件。教学状态版本单调递增，避免重播、重新扫描被旧版本过滤。
- 展示时间戳平移到本次会话，原始采集资源不修改。流量反馈来自模拟器采样，不用前端另写物理模型。
- 教学样式沿用 [固定视觉规范](tutorial-style.md)，不增加局部放大或设备控件副本。共享管式炉窗口在 901–1200px 宽度下将状态卡片排为三列，修复中等窗口下六列重叠，普通使用和教学共用此规则。目录以 2–4 个总结性学习阶段概括课程，实机演示保留本文件所列完整步骤，不提供视频。
