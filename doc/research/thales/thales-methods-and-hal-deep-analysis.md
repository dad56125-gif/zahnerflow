## HAL 的已确认结构

详细证据、地址和反汇编分别见 [生命周期与 ABI 报告](../../../archive/thales-xt-5.9.5-research/analysis/hal_lifecycle/REPORT.md) 和 [传输与恢复报告](../../../archive/thales-xt-5.9.5-research/analysis/hal_transport/报告.md)。已为全部 39 个具名导出函数生成独立反汇编文件；覆盖导出入口不代表全部内部路径已完整证明。

分析对象 FTDIHAL.dll 为 x86，SHA256 `6FD92F33C9D653030CE3F52125996F781BF5555E3A72A3E4916FB90B3FE92D4F`。寄存器传参已由指令确认，Delphi register ABI 是据此形成的判断，尚无完整厂商头文件契约。当前 64 位 Python 不能直接加载此 DLL，普通 `ctypes` cdecl/stdcall 声明也不足以调用这些接口。

- FTDI A/B 两个逻辑通道分别进入 Par/Ser 接口，通过四组匿名管道与四个传输线程交换字节，另有看门狗线程。A/B 的读、写分别共享锁；它们不完全独立。
- 打开设备后设置 D2XX 读写超时 100 ms、USB 参数各 `0x3000`、延迟计时器 2 ms，并执行清队列。设备发现会检查描述、型号及序列号，配置序列号 `65535` 是通配值。
- `USB2BUF` 默认 512、范围 64–8192；`USBWDTIME` 默认 250 ms、范围 100–10000 ms。安装包配置覆盖为 8192 与 5000。配置值不能直接当成所有阻塞操作的总截止时间。
- HAL 内部确有 Windows 消息泵与窗口依赖，包括 `PeekMessageA`、`TranslateMessage`、`DispatchMessageA` 和 `SetParent`；不能按纯粹无界面的读写 DLL 理解。
- Par 8 位缓冲接口长度零可表示 256，返回值包含模 256 求和语义，不应当成实际传输字节数；16 位长度接口有不同边界。超时返回零还需结合超时状态区分。

## 与偶发卡死相关的静态风险

以下是有调用路径依据的风险点，尚未与现场卡死日志或实机抓包建立因果关系。

1. 看门狗监视传输线程循环计数，不是仪器有效应答。线程仍循环但上层协议失步时，不能据此判定通信健康。
2. USB 读取后向同步匿名管道写入；如果消费端停滞，管道写入可能阻塞。USB 的 100 ms 超时不覆盖管道等待、锁等待或整个测量操作。
3. 恢复路径包含 purge、约 20 次 10 ms 等待以及仍未退出时的 `TerminateThread`。若终止发生在持锁阶段，存在后续锁状态异常风险，尚未证明现场发生。
4. 已识别 TX 路径检查 `FT_Write` 状态，但未见依据实际写入长度补发剩余字节；短写可能导致协议丢字节，需实测验证实际触发条件。
5. 关闭路径存在消息泵配合 `Sleep(100)` 的等待循环，局部未见总截止时间；部分互斥等待使用无限等待。持续生产数据时，清空队列的循环也需特别核验。

## 控制接口的真实边界

`ResetHAL` 包含传输清理和排空，不等价于设备测量状态已复位。`SerBreak/SerNMI` 发送内部控制字节，物理作用尚未确认。`NMIorRESET` 使用 FTDI bit mode 控制并等待，实际引脚映射与设备侧时序需要进一步证据。

`SerGetEEPROM` 导出为空；`SerSetEEPROM` 会累积参数并最终调用 `FT_EE_Program`，涉及 USB 描述和序列字段的持久化，不能当成电化学校准 API。`GetPerfData` 在特定参数下重置计数，不能统一当成无副作用读取。分析中没有调用这些接口。

USB2HAL 属于另一条旧硬件路径且经过 UPX 压缩，本次没有达到 FTDIHAL 同等分析深度，不能将两者 ABI 与行为直接互推。

## 对 ZahnerFlow 直接控制设备的意义

目前可以清楚分离“USB 字节传输”和“测量方法执行”。直接替代 HAL 有机会去掉旧窗口、管道和线程恢复逻辑，但仍需恢复启动握手、Remote2/终端封装、命令应答、主机文件服务以及仪器侧方法依赖。把 39 个导出函数全部接通，并不自动获得独立 EIS、LSV 或校准能力。

下一阶段应先建立最小协议状态机和证据表，再对已明确的设备型号进行只读身份/状态验证与传输记录，最后逐项验证 OCP、受控扫描和 EIS。校准写入与 EEPROM 不属于最小直接驱动验证范围。若进入实现阶段，应沿当前进程内 Python 真机驱动边界设计，不重新引入设备服务端口或旧 worker IPC。
