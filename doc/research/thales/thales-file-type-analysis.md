## 已纠正与补充的关键认识

### 偏移校准并非只有调用入口

`script/meas/meas141.is_` 的阅读副本 370–413 行包含 `chkcal` 实现；290–302、1660–1665、2571–2590 行分别包含 `pcaln_p`、`FNavN`、`FNin32`。主代理已回读确认电流/电位偏移采样、平均与参数返回，并另存 [方法摘录](../../../archive/thales-xt-5.9.5-research/methods/02_calibration_meas141.md)。

仍未确认硬件原语/寄存器语义、实际运行版本以及设备专属校准文件。不能从源码存在推导出与当前 `im5.rtm` 等价，也不能把 `calfakj/k/l.bin` 当作这些偏移变量的已知序列化表。

### 一个 HAL 导出名称具有误导性

`FTDIHAL!ParGetLastWriteBuffer` 的 RVA 为 `0x46B2C`，文件偏移为 `0x45F2C`；它调用 VA `0x40007DE8`（RVA `0x7DE8`，文件偏移 `0x71E8`）。主代理用 PE 映射和反汇编回读该内部函数，确认其 NUL 字节串长度循环。不能依据导出名把返回值解释为“最后写缓冲区指针”。此前未明确的内部调用语义因此得到补充。

安装载荷还包含四份不同 D2XX 库：FTDI 驱动目录内 x86/x64 的 `3.2.16.1`、FLINK 根目录 x86 的 `3.02.00`，以及 CPUReset 子目录 x64 的 `3.02.14`。这些是 PE 资源中的版本，不是现场实际加载版本；不得按同名文件替换。

LIB 分析进一步区分出 D2XX 的 x86/x64 静态库与导入库，提供了集成传输层的候选链接材料。它们不包含已经确认的完整仪器测量协议，也不消除 Windows USB 内核驱动的依赖。另有三个 THALES 根目录 SYS 原件并非可识别的 PE，不能因扩展名将其当作 Windows 驱动。

### 两种健康指标不能混用

主代理回读 `DevCli.pdf` 第 8–9 页：DevCli heartbeat 表示距最近工作站通信的毫秒数，EIS 低频测点与刷新间隔会影响它；测量结束后增长也可能正常。它不同于 HAL 内部监视传输线程循环次数的看门狗。单一固定超时不能证明设备已卡死。

该手册第 9 页关于 `GlobalAck%` 的文字写 `0`，相邻示例却发送 `GlobalAck=1`；这是待核对的文档冲突。安装包 INI 中的 `GlobalAck=2` 是另一份配置证据，不能用它直接消解手册冲突。

安装包附带的 `CPUReset/restart.bat` 先三次强制终止 Term131 进程树，再调用 `ZenniumReset.exe vcc`、等待并重启 Term。这里只确认脚本命令顺序；`vcc` 的硬件效果未由脚本证明，也没有执行或将此流程加入自动恢复。

### 安装包不是完整设备现场

RTM 中可定位 IM5/PVI、Remote2、PAD4/FRA 和校准的外部依赖，但字符串不是完整控制流。当前安装目录清单没有找到 `CALIDATX`、`PAD4DEFAULT.BIN`、`FRA_OFFSETS.BIN`，也没有找到 INI 指向的 `sequence09.seq`。这些名字保留为依赖缺口，不用相似示例替代。

### 传输接口与测量方法分别有证据

`ftd2xx.h` 明确声明读写请求长度和实际传输字节数输出指针；其设备信息结构与 HAL 的 x86 枚举布局相符，但句柄字段为指针，不能跨位数照搬结构步长。头文件是 D2XX 契约，不能用来声明 HAL 的不同调用约定。

`ocptest.seq` 可见循环、斜坡、保持和 `ocp(2)`；HTML 与 PDF 给出 LSV 方法说明和序列约束。这些能帮助逐项核对目标测量能力，仍不能替代 USB 上层握手与仪器状态机。三个 HEX 文件通过 Intel HEX 记录校验，只能确认格式与地址记录，不证明适用机型或可以刷写。

### 已有解析器能缩小格式缺口，但要明确数据选择

主代理检查本机 `zahner-analysis 1.1.5` 的 Python 读取实现，并以原始字节作为输入完成交叉核验。五份 ISM 都成功读取，原始样本数为 30、30、15、15、19，核心数组等长且有限；两份 ISC 读出 110、140 条记录，ISS 读出 26 条记录。解析器版本、源码哈希与结果保存在 [只读解析证据](../../../archive/thales-xt-5.9.5-research/analysis/by_type/cross_checks/ism-parser-check.json) 及相邻 ISC、ISS 记录。

两个 30 点 ISM 的默认 getter 只返回 20 点；显式设置 `includeDoubleFrequencies=True` 才返回全部 30 点。这与库中默认选取非重叠频段的实现一致，不是原件被修改，也不据此认定现场数据丢失。后续分析必须明确选择全量点还是非重叠频段。

ISC/ISS 能读取不等于电位缩放、时间轴与所有扩展字段已独立验证。ISF 仍缺对应格式实现。规则目录中的 ISM/ISC 样例也携带数据数组，不能按路径把它们当作纯参数文件。本次没有调用会导出 CSV 的项目包装函数，也没有插值、裁剪或改写原件。
